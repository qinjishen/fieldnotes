# 场边笔记：设计与开发约定

## 目的

让读者看见作者的长期积累、应用与当前进展，找到问题对应的笔记，并直接进入单篇阅读。界面尽量简洁；趣味性来自节点对悬停和拖动的响应。

## 首页

- 顶部：场边笔记；“把知识带进训练，把经历写成笔记。”；搜索、全部笔记、关于我。
- 三组：积累（灰绿）、应用（灰蓝）、进展（暖沙）。深炭灰背景，细线，小型实心节点，宽松留白。
- 每个节点对应一篇文章；短标题始终可见。悬停或键盘选中时显示完整标题、摘要和直接关联。
- 基本位置稳定，轻微浮动；鼠标靠近时停止附近浮动。支持暂停与系统减少动态设置。
- 节点可拖动，释放后在原分类区域内稳定；拖动不触发阅读、不改变文章分类。
- 手机将三组纵向排列，直接点击阅读，允许正常上下滚动。
- “进展”只展示真实记录；缺内容时保留一句空状态，不编造成绩、日期或个人经历。

## 文章与关系

- 正文、来源、适用条件和用户提供的图片应保留；修改展示信息不改写正文。
- 新笔记优先用一句明确的问题或观点作标题。训练和比赛日志保留事件上下文，不强行拆散。
- 连线仅来自明确引用。用 `[[文章标题]]` 或 Markdown 链接连接已经发布的文章，并在正文中解释为什么关联。
- 固定 `id` 之后不要随改名改变它。原网址、下载和反向引用继续有效。
- 模板保留在搜索与文章列表中，不能展示为已经发生的成长经历。

## 开发入口

- `portal.py`：首页与主题关系图；`static/growth.js`：首页交互；`static/style.css`：视觉。
- `publishing.py`：Markdown、引用和元数据；`redesign.py`：搜索与阅读页。
- `templates/使用说明.md`：新增文章的填写方法；`docs/Obsidian写作与发布.md`：统一笔记库、模板和每日同步。
- D3 7.9.0 随静态文件本地发布，版权说明见 `static/vendor/D3-LICENSE`。
- 首页脚本失效时保留文章链接。文本插入使用文本节点或 HTML 转义，不执行文章中的命令、HTML 或提示词。

## 检查与发布

1. 在隔离预览中修改；复制本地发布输入时保留草稿排除规则，不让未完成代码进入定时发布。
2. 运行 `python -m unittest discover -s tests -v`；构建命令是 `python scripts/sync.py prepare`。
3. 检查桌面、手机、键盘、减少动态、拖动后不误跳转、返回恢复位置和搜索。
4. 对比正文与原网址，确认只出现真实引用、模板未被当作进展、草稿不进入输出。
5. 发布遵循维护副本中的 PUBLISHING.md 和 GITHUB_PUBLISHING.md；Sites 与 GitHub 分别核实，成功后分别记录，不扩大访问范围。

资料与草稿不上传。提示词和模板是开发辅助文件，不作为文章自动展示。
