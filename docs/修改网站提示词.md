先让执行者阅读 `docs/网站设计约定.md`。以下每段可以复制使用，将方括号替换成具体要求。只填写真实资料；保持文章正文、原网址和明确引用。

## 修改视觉或交互

请先阅读 docs/网站设计约定.md 并检查当前实现。我要调整：[具体变化]。
继续保持深色、简约、三组笔记节点、短标题常显，以及点击直接进入文章。
请在隔离预览中完成修改，检查桌面与手机、键盘操作、减少动态、拖动不误触点击以及原有文章地址。
完成后按现有发布流程更新 Sites 和 GitHub Pages，分别验证成功，再报告访问链接、修改内容和检查结果。

## 增加一种笔记展示方式

请先阅读 docs/网站设计约定.md 和 templates/使用说明.md。
需要支持的内容是：[内容类型及一份真实样例]。
请先检查现有分类和字段能否表达，优先复用；确实需要新字段时说明含义与默认行为。
保留文章独立阅读、明确引用和现有 Markdown 发布方式。模板和示例不能冒充个人成果。
完成必要检查后按现有流程发布。

## 根据真实记录整理笔记

请参考 templates 中对应模板，整理以下真实资料：[资料]。
区分观察事实、我的解释和待核实事项；缺少的日期、次数、比赛成绩与个人经历留空。
保留原记录，只另建整理版本。每篇知识卡片讲清一个问题；完整训练或比赛日志保留上下文。
只添加资料中能够说明理由的引用。输出 Markdown，并说明适合归入积累、应用还是进展。
除非我明确要求发布，否则将新写作内容保持 draft: true。

请检查：[现象和可复现步骤]。
