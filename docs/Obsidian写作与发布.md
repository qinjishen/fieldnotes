# 在 Obsidian 中维护场边笔记

日常编辑的笔记库是网站维护目录中的“发布文档”。打开其中的 `_开始写作.md`，可以找到全部已发布文章和写作方法。

## 已有文章

网站原有九篇知识卡片已经集中到“网球教学/知识卡片”，两份已公开的日志模板仍在“训练日志/模版”。日常修改这些 Markdown 文件即可，网站会从这里读取。每篇都保留稳定 id，改名或移动不会改变网址。

`content/cards/` 是原有卡片的发布快照；`content/published.json` 保存已发布文章的可移植快照。它们用于 GitHub 重建网站，不作为日常写作入口。原始文件、草稿和 Obsidian 配置不上传。

## 新写一篇

1. 在 Obsidian 中按 Cmd+N 新建笔记，先命名；默认放入“草稿”。
2. 按 Cmd+P，选择“模板：插入模板 / Templates: Insert template”。
3. 选择知识卡片、训练日志、比赛复盘或阶段进展。模板会生成固定 id，文章正文可以直接编辑。
4. 写完后把 draft 改为 false，再把文件从“草稿”移入“网球教学”“健身”或“训练计划”。
5. 保留 id；需要改变首页位置时，修改 stage。event_date 只填写真实发生日期，不确定可留空。

模板源文件在 `templates/obsidian/`。本机 Obsidian 插入模板使用“发布文档/_写作模板”；该目录不会作为文章发布。模板中的时间编号由 Obsidian 核心模板功能生成，不需要安装社区插件。

## 实时预览

使用 Obsidian 的“实时预览”编辑模式，可以看到格式化后的标题、列表、表格和引用，同时直接编辑文字。Cmd+E 可切换阅读与编辑。网页 HTML 由发布流程生成，无需手写或上传 HTML。

通过 `[[文章标题]]` 或 `[[文章别名]]` 引用笔记，网站会建立连接与反向引用。图片放在“附件”；网站只复制实际引用的文件。

## 维护人员

`scripts/setup_obsidian.py` 负责迁移和配置现有本地笔记库。它保留正文、来源、关系和 id，迁移前备份被修改的本地文件，并检查文章集合。重复运行会保留已经写入的正文。

本地 `.obsidian/fieldnotes.json` 显式指定哪些原有卡片已交给 Obsidian 编辑。发布程序只在该配置存在时切换来源，并为 GitHub 生成可独立读取的快照。不要删除此配置或手动复制同 id 的第二份文章进入发布范围。

运行前后的备份位于维护目录 `.publish-state/obsidian-backup-*`，不进入 GitHub 或网站。
